# Users API

Готовое приложение FastAPI + SQLAlchemy + Microsoft SQL Server. Весь код приложения находится в main.py. Docker не используется.

## Запуск

Требуется Python 3.10+, работающий Microsoft SQL Server и Microsoft ODBC Driver 18 for SQL Server.
Для вашего экземпляра MSSQLSERVER уже указаны localhost и Windows-аутентификация. Запускайте приложение под своей обычной учётной записью Windows.

Откройте папку проекта в PyCharm и запустите run.py. Он создаст виртуальное окружение, установит зависимости и запустит API. Через терминал:

```powershell
py run.py
```

Если зависимости уже установлены, можно сразу запускать main.py кнопкой Run в PyCharm.
Swagger: http://127.0.0.1:8000/docs

При запуске Python-код создаёт базу users_db, если она отсутствует, и таблицу users (id, name, email, age). Для создания базы нужны права CREATE DATABASE; для существующей базы нужны права на таблицу и её создание.

## Таблица товаров

Модель `Product` в `main.py` описывает таблицу `products` с шестью полями:

| Поле | Тип | Назначение |
|---|---|---|
| id | Integer | Первичный ключ, присваивается автоматически |
| name | Unicode(100) | Название товара |
| description | Unicode(1000) | Описание товара |
| price | Numeric(12, 2) | Цена с двумя знаками после запятой |
| quantity | Integer | Количество, по умолчанию 0 при вставке через SQLAlchemy |
| category | Unicode(100) | Категория товара |

Все поля обязательны (не допускают NULL). Таблица создаётся при запуске приложения через `Base.metadata.create_all`. Отдельные HTTP-методы для товаров пока не добавлены.

## Ручки

| Функция | HTTP | Адрес |
|---|---|---|
| get_all_users | GET | /users |
| get_user | GET | /users/{user_id} |
| post_user | POST | /users |
| put_user | PUT | /users/{user_id} |
| delete_user | DELETE | /users/{user_id} |

POST принимает name, email, age. ID присваивается SQL Server. PUT изменяет только переданные поля. Email уникален. Для отсутствующего пользователя возвращается 404, для повторяющегося email — 409, для неверных данных — 422.

```json
{"name": "Анна", "email": "anna@example.com", "age": 25}
```

## Адрес получения в объявлении

`POST /ads` принимает обязательные поля адреса: `city` (город, до 100 символов),
`district` (район, до 100), `street` (улица, до 200), `house` (дом, до 30).
Дом задаётся строкой: можно указать `12А`, `7/1` или `12, корпус 2`.
ID объявления (`id`) присваивается автоматически и возвращается вместе с адресом
в ответах POST, GET и PUT. Пример создания (пользователь 1 должен существовать):

```json
{
  "owner_id": 1,
  "title": "Стол",
  "description": "Забрать по указанному адресу",
  "price": "1000.00",
  "city": "Казань",
  "district": "Советский",
  "street": "Мира",
  "house": "12А"
}
```

`PUT /ads/{ad_id}` изменяет переданные поля адреса. Пустые строки и `null`
при создании и изменении адреса отклоняются с кодом 422.
При перезапуске приложение добавит недостающие столбцы в существующую таблицу
`ads` SQL Server; нужны права ALTER TABLE. Старые объявления сохраняются,
их незаполненные поля адреса возвращаются как `null` до изменения через PUT.
Проверено 10 HTTP-тестами на SQLite; обновление схемы на рабочем SQL Server
в рамках этой проверки не запускалось.

## Настройка другого сервера

Переименуйте .env.example в .env и измените DATABASE_URL. Файл читается из папки main.py, независимо от текущего каталога запуска. По умолчанию используется Windows-аутентификация. Для SQL-аутентификации можно использовать URL вида mssql+pyodbc://USER:PASSWORD@SERVER/users_db?driver=ODBC+Driver+18+for+SQL+Server&TrustServerCertificate=yes (специальные символы пароля должны быть URL-кодированы).

TrustServerCertificate=yes позволяет локальное подключение к самоподписанному сертификату. Изменение шифрования и реестра SQL Server не требуется.

## Проверка API

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

HTTP-тесты используют отдельную временную SQLite-базу исключительно как тестовую среду. Рабочее приложение всегда подключается к MS SQL Server; автоматической подмены рабочей базы нет. Тесты не обращаются к вашим пользователям в SQL Server.

## Ошибка Windows-аутентификации

Если драйвер сообщает «В пакете безопасности отсутствуют учетные данные» (0x8009030E), запускайте проект напрямую из PyCharm или обычного пользовательского PowerShell. Такая ошибка возникает в ограниченном окружении, где нет Windows-учётных данных SSPI; она не означает, что сертификат недоверенный.
